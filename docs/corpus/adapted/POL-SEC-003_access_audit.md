## 1. Назначение

Настоящая политика определяет порядок проведения аудита доступов к информационным системам Synapse Corp, требования к ведению журналов аудита и меры реагирования на выявленные нарушения. Регулярный аудит является обязательным элементом системы информационной безопасности согласно ГОСТ Р ИСО/МЭК 27001-2021, раздел A.12.4.

---

## 2. Цели аудита

- Убедиться, что каждый сотрудник имеет только те права, которые необходимы для его работы
- Выявить и устранить избыточные, устаревшие и несанкционированные доступы
- Подтвердить соответствие фактических прав матрице доступов (`POL-SEC-004`)
- Зафиксировать нарушения политик для дальнейшего реагирования

---

## 3. Виды аудита

| Вид | Периодичность | Триггер | Ответственный |
|---|---|---|---|
| Плановый (полный) | Ежеквартально | Календарный план | IT / Security |
| Онбординг-аудит | На 30-й день работы сотрудника | Выход нового сотрудника | IT |
| Аудит при смене роли | При изменении грейда / должности | Уведомление от HR | IT |
| Аудит при увольнении | В день последнего рабочего дня | Уведомление от HR | IT |
| Внеплановый | По необходимости | Инцидент, подозрительная активность | Security |

---

## 4. Процедура планового аудита

### 4.1 Подготовка

```
За 5 рабочих дней до аудита:
1. IT-отдел формирует список всех активных пользователей и их прав
2. HR предоставляет актуальный список сотрудников с ролями и датами найма/увольнения
3. Сравнение: фактические права vs. матрица доступов (POL-SEC-004)
```

### 4.2 Проведение

Для каждой системы из `POL-SEC-004` проверяется:
- Список активных аккаунтов соответствует списку действующих сотрудников
- Уровень прав каждого аккаунта соответствует роли сотрудника
- Отсутствуют аккаунты уволенных сотрудников
- Временные доступа не превысили разрешённый срок
- Сервисные аккаунты используются только по назначению

### 4.3 Документирование результатов

По итогам аудита формируется отчёт:

```markdown
# Отчёт об аудите доступов
Дата: ДД.ММ.ГГГГ
Ответственный: Имя

## Проверенные системы
[Список систем]

## Выявленные несоответствия
| Система | Пользователь | Фактический доступ | Требуемый | Статус |
|---|---|---|---|---|
| ... | ... | ... | ... | Устранено / В работе |

## Статистика
- Проверено аккаунтов: N
- Выявлено несоответствий: N
- Устранено: N

## Действия
[Список действий с ответственными и сроками]
```

### 4.4 Устранение несоответствий

| Тип несоответствия | Срок устранения |
|---|---|
| Аккаунт уволенного сотрудника | Немедленно (в день обнаружения) |
| Избыточные права | 1 рабочий день |
| Нарушение политики временного доступа | 1 рабочий день |
| Несанкционированный сервисный аккаунт | Немедленно + расследование |

## 5. Журналы аудита

### 5.1 Что логируется

| Событие | Система | Срок хранения |
|---|---|---|
| Вход / выход пользователя | Все системы | 6 месяцев |
| Изменение прав доступа | GitLab, Jira, инфраструктура | 1 год |
| Доступ к продакшн-окружению | SSH-логи, БД-логи | 1 год |
| Запросы к продакшн-БД | Qdrant, Neo4j | 6 месяцев |
| CI/CD деплои | GitLab CI | 1 год |
| Изменения в матрице доступов | Jira (тикеты) | Бессрочно |

### 5.2 Защита журналов

- Журналы аудита доступны только Admin (уровень 5)
- Журналы защищены от изменения и удаления
- Резервная копия журналов создаётся ежедневно

---

## 6. Метрики эффективности аудита

| Метрика | Целевое значение |
|---|---|
| Аккаунты уволенных сотрудников, найденные при аудите | 0 |
| Избыточных прав, выявленных при плановом аудите | < 5% от общего числа аккаунтов |
| Несоответствий, устранённых в срок | 100% |
| Покрытие аудитом онбординга (30-й день) | 100% новых сотрудников |
