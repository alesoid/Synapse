## 1. Проблема

Корпоративные знания в IT-компании хранятся в разрозненных источниках: PDF-регламенты, Markdown-стандарты, таблицы доступов, внутренние вики. Сотрудник тратит от 15 до 40 минут на поиск ответа на рабочий вопрос — и часто не находит его вовсе, обращаясь к коллегам.

Существующие подходы не решают проблему:

- **Полнотекстовый поиск** (Confluence, Notion) не понимает смысл запроса и не учитывает связи между документами.
- **Обычный RAG** (векторный поиск) теряет контекст: не видит что регламент А ссылается на политику Б, которая определяет роль В.
- **Облачные LLM** (ChatGPT, Claude) недопустимы в закрытом корпоративном контуре из-за требований ФЗ-152 и политики ИБ.
- **Ручное разграничение доступа** не масштабируется: Junior видит то что не должен, или наоборот — не находит нужное из-за избыточных ограничений.

**Ключевая боль:** сотрудник не может быстро получить точный ответ по внутренним документам с учётом своей роли и уровня доступа.

Также, с точки зрения управления знаниями (Knowledge Management) компания сталкивается с тремя системными дисфункциями:

- **Пробелы в знаниях не видны.** Когда сотрудник не находит ответ, этот факт нигде не фиксируется. Организация не знает, каких документов не хватает.
- **Знания стареют незаметно.** Регламент трёхлетней давности выглядит так же, как актуальный. Система не сигнализирует об устаревших данных.
- **Онтология не управляется.** «Процесс деплоя», «pipeline выкатки» и «релизный процесс» — одно и то же, но в разных документах. Граф знаний без явной онтологии фрагментирован.

## 2. Предлагаемое решение

**Synapse** — корпоративная платформа анализа знаний на основе GraphRAG, работающая полностью в закрытом контуре (on-premise / air-gapped).

Ключевая идея: вместо простого векторного поиска система строит **граф знаний** (Knowledge Graph) из корпоративных документов — фиксирует сущности (роли, процессы, системы, политики) и связи между ними. При запросе пользователя система комбинирует векторный поиск и граф-траверсал, получая контекстно-обогащённый ответ.

**Два режима работы:**

- **Q&A режим** — сотрудник задаёт вопрос на русском языке, система возвращает ответ со ссылками на источники с учётом роли пользователя (RBAC).
- **Explorer режим** — аналитик / Admin исследует граф знаний визуально, находит неочевидные связи между документами, процессами и ролями.

### **2.1 Архитектурные принципы**

|Принцип|Описание|
|---|---|
|On-premise by default|Система разворачивается в закрытом корпоративном контуре, без обращений к внешним API и облачным сервисам|
|Retrieval before generation|LLM получает контекст только после поиска по корпусу — генерация без retrieval запрещена|
|Graph-enhanced context enrichment|Векторный поиск дополняется графовым траверсалом для получения связанного контекста|
|Security enforced before inference|Проверка прав доступа и фильтрация входящего запроса выполняются до передачи данных в LLM|
|Observability-first pipeline|Каждый этап обработки запроса трейсируется и измеряется — от ingestion до генерации ответа|
|Modular infrastructure|Компоненты системы независимы и заменяемы: LLM, vector DB, graph DB меняются без переписывания логики|
|Separation of data plane and control plane|Оркестрация (LangGraph, API) и хранилища данных (Qdrant, Neo4j, vLLM) разделены архитектурно|
|Ontology-driven knowledge graph|Граф знаний строится на основе явного словаря сущностей предметной области — одна сущность под разными именами создаёт один узел, а не дубли|

### **2.2 Принципы безопасности**

|Принцип|Описание|
|---|---|
|Retrieval-time access filtering|Фильтрация по уровню доступа применяется в момент поиска, а не после генерации ответа|
|Zero external APIs|Никакие данные не покидают периметр — запрещены обращения к OpenAI, Anthropic и любым внешним сервисам|
|Isolated deployment|Все компоненты работают в изолированной сети без доступа в интернет|
|Chunk-level access control|Разграничение доступа применяется на уровне каждого чанка в Qdrant и каждого узла в Neo4j|
|Auditability|Все запросы, роли пользователей и результаты поиска логируются для последующего аудита|
|Prompt injection mitigation|Входящие запросы проверяются на паттерны prompt injection до передачи в LLM|
|Output filtering|Ответ LLM проверяется на наличие PII и нежелательного контента перед отдачей пользователю|

## 3. Ценностное предложение (Value Proposition)

| Ценность | Описание |
|---|---|
| **Точность через граф** | GraphRAG находит неочевидные связи между документами, которые теряет обычный RAG. Меньше галлюцинаций, больше контекста. |
| **Безопасность через RBAC** | Разграничение доступа на уровне чанков: Junior не получит ответ по документу уровня Manager, даже если спросит напрямую. |
| **Суверенитет через on-premise** | Система работает полностью локально — никаких обращений к OpenAI/Anthropic. Соответствие ФЗ-152, политикам ИБ, требованиям импортозамещения. |
| **Управление знаниями, а не только поиск** | Система не просто отвечает на вопросы — она выявляет пробелы в корпусе, сигнализирует об устаревших документах и поддерживает согласованную онтологию предметной области. |

## 4. Целевая аудитория

**Основные пользователи — сотрудники IT-компании:**

| Роль | Кто это | Основная потребность |
|---|---|---|
| Junior | Новый сотрудник (0–1 год) | Быстро найти регламент или инструкцию не отвлекая коллег |
| Middle | Разработчик (1–3 года) | Найти технический стандарт или архитектурное решение |
| Senior | Опытный специалист (3+ лет) | Исследовать связи между архитектурными решениями и политиками |
| Manager | Руководитель | Получить доступ к HR-политикам и процессам согласований |
| Admin / Analyst | Администратор системы | Управлять корпусом документов, исследовать граф знаний |

**Вторичная аудитория:** IT-директор, CISO (заинтересованы в безопасности и соответствии требованиям).

## 5. Рассмотренные альтернативы

| Альтернатива | Почему не подходит |
|---|---|
| Обычный RAG (векторный поиск) | Теряет связи между документами, высокий процент галлюцинаций на сложных запросах |
| Облачный ChatGPT / Claude API | Нарушает требования ФЗ-152, политику ИБ, данные уходят за периметр |
| Confluence / Notion поиск | Полнотекстовый поиск без понимания смысла, нет RBAC на уровне чанков |
| Готовые Enterprise RAG решения | Зарубежные вендоры (недоступны в РФ или несут санкционные риски), нет GraphRAG |
| Дообучение (fine-tuning) модели | Дорого, требует GPU-кластер, модель устаревает при обновлении документов |

## 6. Поэтапная стратегия: PoC → MVP → Scale

### PoC / local-lite (до 25 мая 2026)
**Цель:** проверить базовый GraphRAG pipeline на Mac M3 8 GB RAM без зависимости от GPU.
**Гипотеза:** гибридный поиск (вектор + граф) на Markdown-корпусе IT-регламентов даёт более релевантный контекст, чем vector-only retrieval, и сохраняет RBAC-изоляцию.
**Артефакты:** рабочий local-lite прототип, Markdown ingestion, mock LLM, mock/lightweight embeddings, базовый Qdrant/Neo4j retrieval, RBAC smoke-тесты, проверяемый LangGraph flow.

### MVP (текущая разработка, до 30 мая 2026)

**Цель:** выпустить демонстрируемую систему для защиты, где ключевая гипотеза GraphRAG подтверждается не только архитектурой, но и работающим End-to-End pipeline.

MVP делится на два режима:

- **local-lite** — разработка на Mac M3 8 GB RAM: mock LLM, mock/lightweight embeddings, Markdown corpus, unit/integration tests, smoke-проверки API и LangGraph flow.
- **gpu-demo** — финальное развёртывание на сервере с RTX 4090 24 GB VRAM через Docker Compose: vLLM + Qwen2.5-14B-AWQ, Qdrant, Neo4j, FastAPI, UI, Langfuse, Prometheus/Grafana.

**Скоуп MVP:**

- Q&A режим с гибридным поиском GraphRAG: `0.7 · vector + 0.3 · graph`.
- Ingestion Markdown-корпуса из `docs/corpus/adapted`.
- Метаданные документов из `docs/corpus/corpus_manifest.json`.
- Chunking 500 токенов с overlap 50.
- Qdrant для vector search.
- Neo4j для Knowledge Graph и graph traversal.
- RBAC на уровне чанков и узлов графа.
- Input/Output Guardrails.
- LangGraph pipeline с именованными нодами и retry-логикой.
- Mock LLM для local-lite разработки.
- vLLM backend для gpu-demo.
- Ответы с источниками, `quality_score`, `confidence_score`.
- Knowledge Gap Detection.
- Минимальный Web UI.
- Langfuse traces и Prometheus/Grafana metrics в gpu-demo.
- Evaluation report и load test report.
- Demo video 5-7 минут.

**Критерий успеха:** комиссия видит работающий GraphRAG pipeline, RBAC без утечек, локальную LLM на GPU, трассировку, метрики и отчёты evaluation/load test.

### Scale (по результатам тестирования MVP)
**Цель:** превратить MVP в production-ready платформу для реального Enterprise-заказчика.

**Направления развития:**
- Kubernetes (Helm charts, автомасштабирование)
- JWT-аутентификация и интеграция с корпоративным LDAP/AD
- MLOps pipeline (автоматическое переиндексирование при обновлении документов)
- SLA и мониторинг production-уровня
- **Document Preparation (расширенный)** — OCR промышленного качества (Tesseract 5 / Azure Document Intelligence self-hosted), автоматическая классификация `access_level` через LLM, коннекторы к Confluence и GitLab
- **Multi-Agent расширение** — SupervisorAgent + доменные агенты по типу документа (PolicyAgent, TechnicalAgent, HRAgent)
- **Knowledge Decay Detection** — визуализация устаревших узлов графа в Explorer режиме, автоматические уведомления владельцам документов
- **Tacit Knowledge Capture** — механизм захвата неявных знаний: фиксация экспертных ответов из Slack/почты как новых документов корпуса
- **Knowledge Health Dashboard** — панель управления состоянием корпуса: покрытие тем, пробелы, устаревшие документы, частота обращений

## 7. Допущения и ограничения

**Допущения и ограничения:**
- Корпус документов на русском языке 
- Документы доступны в форматах PDF, DOCX, XLSX, Markdown, CSV; сканированные PDF и страницы со схемами обрабатываются через Document Preparation Pipeline
- Mac M3 8GB RAM используется только как local-lite среда для разработки, моков, unit/integration tests и lightweight smoke-проверок; полный LLM/observability/database stack на нём не запускается.
- Полный inference/runtime контур проверяется на сервере с RTX 4090 24 GB VRAM.
- Для демо достаточно 20–50 документов
- Если возникает конфликт между широтой функций и стабильностью демо, приоритет отдаётся стабильному End-to-End GraphRAG pipeline.
- OCR и Vision preprocessing являются Should Have и могут быть перенесены в Scale без нарушения базовой ценности MVP.
- Никаких внешних API (OpenAI, Anthropic, Yandex GPT)
- Только open source модели с поддержкой русского языка
- MVP без JWT-аутентификации (dropdown ролей для демо)
- Ollama остаётся optional fallback для local-lite, но не является основным LLM runtime для MVP-разработки
- Без поддержки real-time обновления графа (только batch ingestion)
- Слой 2 Document Preparation (Qwen2.5-VL для чертежей) реализуется при наличии времени и свободной VRAM.

## 8. Высокоуровневые риски

| Риск | Влияние | Митигация |
|---|---|---|
| Низкое качество извлечения сущностей | Высокое | Few-shot промпты, валидация графа после каждого ingestion |
| Latency на CPU / Mac 8 GB неприемлема | Высокое | Полный стек разрабатывается на GPU Dev VM с RTX 4090; Mac используется только как local-lite среда |
| Расхождение кода и диаграмм | Критичное | Принцип: сначала диаграмма, потом код |
| Нехватка времени на реализацию MVP | Критичное | Сокращение scope до стабильного End-to-End GraphRAG pipeline; OCR/Vision/расширенный Explorer остаются Should Have |
