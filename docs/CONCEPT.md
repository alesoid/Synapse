## 1. Проблема

Корпоративные знания в IT-компании хранятся в разрозненных источниках: PDF-регламенты, Markdown-стандарты, таблицы доступов, внутренние вики. Сотрудник тратит от 15 до 40 минут на поиск ответа на рабочий вопрос — и часто не находит его вовсе, обращаясь к коллегам.

Существующие подходы не решают проблему:

- **Полнотекстовый поиск** (Confluence, Notion) не понимает смысл запроса и не учитывает связи между документами.
- **Обычный RAG** (векторный поиск) теряет контекст: не видит что регламент А ссылается на политику Б, которая определяет роль В.
- **Облачные LLM** (ChatGPT, Claude) недопустимы в закрытом корпоративном контуре из-за требований ФЗ-152 и политики ИБ.
- **Ручное разграничение доступа** не масштабируется: Junior видит то что не должен, или наоборот — не находит нужное из-за избыточных ограничений.

**Ключевая боль:** сотрудник не может быстро получить точный ответ по внутренним документам с учётом своей роли и уровня доступа.

---

## 2. Предлагаемое решение

**Synapse** — корпоративная платформа анализа знаний на основе GraphRAG, работающая полностью в закрытом контуре (on-premise / air-gapped).

Ключевая идея: вместо простого векторного поиска система строит **граф знаний** (Knowledge Graph) из корпоративных документов — фиксирует сущности (роли, процессы, системы, политики) и связи между ними. При запросе пользователя система комбинирует векторный поиск и граф-траверсал, получая контекстно-обогащённый ответ.

**Два режима работы:**

- **Q&A режим** — сотрудник задаёт вопрос на русском языке, система возвращает ответ со ссылками на источники с учётом роли пользователя (RBAC).
- **Explorer режим** — аналитик / Admin исследует граф знаний визуально, находит неочевидные связи между документами, процессами и ролями.

---

## 3. Ценностное предложение (Value Proposition)

| Ценность | Описание |
|---|---|
| **Точность через граф** | GraphRAG находит неочевидные связи между документами, которые теряет обычный RAG. Меньше галлюцинаций, больше контекста. |
| **Безопасность через RBAC** | Разграничение доступа на уровне чанков: Junior не получит ответ по документу уровня Manager, даже если спросит напрямую. |
| **Суверенитет через on-premise** | Система работает полностью локально — никаких обращений к OpenAI/Anthropic. Соответствие ФЗ-152, политикам ИБ, требованиям импортозамещения. |

---

## 4. Целевая аудитория

**Основные пользователи — сотрудники IT-компании:**

| Роль | Кто это | Основная потребность |
|---|---|---|
| Junior | Новый сотрудник (0–1 год) | Быстро найти регламент или инструкцию не отвлекая коллег |
| Middle | Разработчик (1–3 года) | Найти технический стандарт или архитектурное решение |
| Senior | Опытный специалист (3+ лет) | Исследовать связи между архитектурными решениями и политиками |
| Manager | Руководитель | Получить доступ к HR-политикам и процессам согласований |
| Admin / Analyst | Администратор системы | Управлять корпусом документов, исследовать граф знаний |

**Вторичная аудитория:** IT-директор, CISO (заинтересованы в безопасности и соответствии требованиям).

## 5. Рассмотренные альтернативы

| Альтернатива | Почему не подходит |
|---|---|
| Обычный RAG (векторный поиск) | Теряет связи между документами, высокий процент галлюцинаций на сложных запросах |
| Облачный ChatGPT / Claude API | Нарушает требования ФЗ-152, политику ИБ, данные уходят за периметр |
| Confluence / Notion поиск | Полнотекстовый поиск без понимания смысла, нет RBAC на уровне чанков |
| Готовые Enterprise RAG решения | Зарубежные вендоры (недоступны в РФ или несут санкционные риски), нет GraphRAG |
| Дообучение (fine-tuning) модели | Дорого, требует GPU-кластер, модель устаревает при обновлении документов |

## 6. Поэтапная стратегия: PoC → MVP → Scale

### PoC (текущий этап, 2–4 недели)
**Цель:** проверить что GraphRAG на корпоративных документах даёт лучшее качество ответов чем обычный векторный поиск.

**Гипотеза:** гибридный поиск (вектор + граф) на корпусе IT-регламентов даёт точность ответов >80% на тестовом наборе из 20 вопросов.

**Артефакты:** рабочий прототип, сравнительные метрики GraphRAG vs векторный поиск, настроенная инфраструктура.

### MVP (текущая разработка, до 6 июня 2026)
**Цель:** выпустить работающую систему с полным набором функций для ограниченной аудитории (демо, защита диплома).

**Скоуп MVP:**
- Q&A режим с гибридным поиском (GraphRAG)
- RBAC на уровне чанков (5 ролей)
- Input/Output Guardrails
- Explorer режим для Admin
- Полная локальность (on-premise, vLLM + Qwen2.5)
- Observability (Langfuse, Prometheus, Grafana)

**Критерий успеха:** система принята комиссией, все критерии приёмки диплома выполнены.

### Scale (после защиты)
**Цель:** превратить MVP в production-ready платформу для реального Enterprise-заказчика.

**Направления развития:**
- Kubernetes (Helm charts, автомасштабирование)
- JWT-аутентификация и интеграция с корпоративным LDAP/AD
- Multimodal RAG (работа с изображениями и таблицами в документах)
- MLOps pipeline (автоматическое переиндексирование при обновлении документов)
- SLA и мониторинг production-уровня

## 7. Допущения и ограничения

**Допущения:**
- Корпус документов на русском и английском языках
- Документы доступны в форматах PDF, Markdown, CSV
- Развёртывание на одном GPU-сервере (не кластер)
- Для демо достаточно 20–50 документов

**Ограничения:**
- Никаких внешних API (OpenAI, Anthropic, Yandex GPT)
- Только open source модели с поддержкой русского языка
- MVP без JWT-аутентификации (dropdown ролей для демо)
- Без поддержки real-time обновления графа (только batch ingestion)

## 8. Высокоуровневые риски

| Риск | Влияние | Митигация |
|---|---|---|
| Низкое качество извлечения сущностей | Высокое | Few-shot промпты, валидация графа после каждого ingestion |
| Latency на CPU неприемлема | Высокое | GPU сервер (Yandex Cloud T4) для prod и демо |
| Расхождение кода и диаграмм | Критичное | Принцип: сначала диаграмма, потом код |
| Нехватка времени на документацию | Высокое | Фаза 2 целиком выделена под документацию |
