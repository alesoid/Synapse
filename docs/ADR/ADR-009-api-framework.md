# ADR-009: API Framework — FastAPI

**Статус:** Принято  
**Дата:** 11 мая 2026  
**Автор:** Алеся Мороз

---

## Scope

| Этап | Что реализовано | Статус |
|---|---|---|
| **MVP** | FastAPI + uvicorn, синхронные и стриминговые эндпоинты, OpenAPI автогенерация | ✅ Текущее решение |
| **Scale** | Без изменений — FastAPI масштабируется до production нагрузок; при необходимости горизонтальное масштабирование через Kubernetes | 🔜 Без изменений |

---

## Контекст

Synapse требует API Gateway между React UI и backend-сервисами (LangGraph агент, Qdrant, Neo4j). Ключевые требования:

- Async-обработка запросов (LangGraph агент — долгие операции)
- Streaming-ответы (токены передаются по мере генерации, FR-06)
- Автоматическая генерация OpenAPI документации
- Валидация входящих данных (роль пользователя, параметры запроса)
- Простота интеграции с LangGraph и Python-экосистемой

---

## Решение

**FastAPI 0.110+** с uvicorn ASGI сервером.

```python
@app.post("/query")
async def query(
    request: QueryRequest,
    user_level: int = Depends(role_to_access_level)
) -> StreamingResponse:
    return StreamingResponse(
        agent.astream(request.query, user_level),
        media_type="text/event-stream"
    )
```

## Альтернативы рассмотрены

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Django REST Framework** | Зрелый фреймворк, богатая экосистема, ORM | Синхронный по умолчанию, избыточен для API-only сервиса без ORM-задач, тяжелее | **Отклонён** |
| **Flask + flask-restx** | Лёгкий, гибкий, знакомый большинству Python-разработчиков | Нет нативного async, streaming требует workarounds, нет автовалидации Pydantic | **Отклонён** |
| **aiohttp** | Низкоуровневый async, максимальная гибкость | Нет автогенерации OpenAPI, нет встроенной валидации, выше трудозатраты | **Отклонён** |
| **Litestar** | Современная альтернатива FastAPI, высокая производительность | Меньше community и примеров, выше риск для MVP | **Отклонён** |
| **gRPC** | Высокая производительность, строгая типизация | Не поддерживается браузером напрямую, избыточен для внутреннего API | **Отклонён** |

## Trade-offs

**Плюсы FastAPI:**
- Нативный async/await — LangGraph агент запускается без блокировки event loop
- `StreamingResponse` + `astream` — streaming ответов без дополнительных библиотек
- Pydantic v2 — автоматическая валидация входящих запросов и сериализация ответов
- OpenAPI UI (`/docs`) — автогенерируемая документация, полезна при демо
- `Depends()` — чистая реализация dependency injection для RBAC (`role_to_access_level`)
- Самый популярный Python async фреймворк — богатая экосистема, LangChain/LangGraph интеграции

**Минусы FastAPI:**
- Pydantic v2 ломает совместимость с некоторыми LangChain компонентами (фиксируется версиями в requirements.txt)
- Uvicorn — однопоточный воркер по умолчанию; для production нагрузки нужен Gunicorn + несколько uvicorn воркеров (вне скоупа MVP)

---

## Последствия

- API Gateway реализован в `/backend/api/`
- Все эндпоинты используют `async def` и Pydantic-модели для валидации
- `Depends(role_to_access_level)` применяется ко всем защищённым эндпоинтам
- OpenAPI документация доступна на `/docs` — используется при демо для демонстрации API
- В Scale: Gunicorn с несколькими uvicorn воркерами или K8s горизонтальное масштабирование

---

## Compliance & Ethics

**Регуляторное соответствие:**
- FastAPI развёртывается локально — данные не покидают периметр
- Лицензия **MIT** — коммерческое использование без ограничений
- Все входящие запросы валидируются Pydantic до передачи в бизнес-логику — снижается поверхность атаки

**Этические риски и меры снижения:**
- Риск обхода RBAC через прямые вызовы внутренних эндпоинтов. Мера: `Depends(role_to_access_level)` применяется на уровне каждого эндпоинта, внутренние сервисы (Qdrant, Neo4j) недоступны снаружи Docker-сети
- Риск утечки stack trace в ответе при необработанном исключении. Мера: глобальный exception handler возвращает обезличенное сообщение об ошибке без внутренних деталей реализации
