# ADR-007: Hybrid Search Merge Formula — Reciprocal Rank Fusion (RRF)

**Статус:** Принято  
**Дата:** 11 мая 2026 (обновлено 28 мая 2026)  
**Автор:** Алеся Мороз

---

## Scope

| Этап | Что реализовано | Статус |
|---|---|---|
| **MVP** | Reciprocal Rank Fusion (RRF) с `k=60`; граф-сигнал нормирован по `match_count` и `hop_distance`; параметр `alpha` настраивается через `HYBRID_ALPHA` | ✅ Текущее решение |
| **Scale** | Cross-encoder reranker поверх топ-20 кандидатов; адаптивные веса на основе типа запроса | 🔜 Вне скоупа MVP |

---

## Контекст

Synapse реализует гибридный поиск: векторный (Qdrant, семантическое сходство) и графовый (Neo4j, traversal по связям сущностей). Результаты двух поисков необходимо объединить в единый ранжированный список для передачи в LLM. Ключевые требования:

- Устойчивость к выбросам в скорах (cosine similarity не нормирован одинаково с графовым скором)
- Оба источника должны влиять на итоговый ранг — граф не должен быть декоративным
- Возможность настройки весов через env var без изменения кода
- Детерминированное слияние результатов (воспроизводимость)

---

## Решение

**Reciprocal Rank Fusion (RRF)** с graph-signal нормированием:

```python
# backend/query/pipeline.py  — функция _merge()

k = 60          # RRF constant (стандарт: 60)
alpha = HYBRID_ALPHA    # вклад вектора, default 0.7
graph_alpha = 1 - alpha  # вклад графа,   default 0.3

# Нормировка графового сигнала
max_match = max((r.match_count for r in graph_map.values()), default=0) or 1

# Векторный вклад: ранжирование по cosine score descending
for rank, chunk in enumerate(sorted(vector_chunks, key=lambda c: c.score, reverse=True)):
    rrf[key] += alpha / (k + rank + 1)

# Графовый вклад: ранжирование по match_count desc + hop_distance asc
for rank, result in enumerate(sorted_graph):
    graph_signal = (result.match_count / max_match) / max(result.hop_distance, 1)
    rrf[key] += graph_alpha * graph_signal / (k + rank + 1)
```

**Коэффициенты:** `alpha=0.7` (вектор), `1-alpha=0.3` (граф).  
Настраиваются через env var `HYBRID_ALPHA=0.7` без изменения кода.

## Альтернативы рассмотрены

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Взвешенная линейная комбинация `0.7·v + 0.3·g`** | Прозрачность: вклад явно задан; просто объяснить | Требует нормализации min-max; чувствительна к выбросам; cosine similarity и графовый скор имеют разные шкалы | **Заменена RRF** в процессе реализации |
| **0.5 · vector + 0.5 · graph** | Равный вклад обоих источников | Граф MVP содержит ~50-100 узлов — его покрытие ниже векторного; равный вес снижает точность | **Отклонён** |
| **Только векторный поиск (alpha=1.0)** | Проще, нет зависимости от качества графа | Теряются связи между документами — ключевое преимущество GraphRAG | **Отклонён** (противоречит концепции) |
| **Cross-encoder reranker** | Наилучшее качество ранжирования | Требует отдельной модели, +latency ~2-3 сек, избыточен для MVP | **Отклонён для MVP**, запланирован для Scale |
| **LLM-based reranking** | Высокое качество, гибкость | Двойной вызов LLM — удваивает latency и стоимость инференса | **Отклонён** |

## Trade-offs

**Плюсы RRF:**
- Не требует нормализации скоров — работает непосредственно с рангами, устойчив к выбросам
- Хорошо работает без тюнинга: `k=60` — стандартный параметр, подтверждённый в литературе
- Прозрачность: вклад вектора (`alpha`) и графа (`1-alpha`) по-прежнему настраиваемы
- `graph_signal` нормирован по `match_count / max_match` и `hop_distance` — граф влияет на результат пропорционально качеству совпадения сущностей

**Минусы RRF:**
- Менее интуитивен, чем линейная комбинация — сложнее объяснить комиссии
- Итоговый `retrieval_score` — это RRF-значение, а не привычный 0–1 скор (не интерпретируется как «процент релевантности»)
- Два канала данных слиты через ранги, а не через значения — потеря информации об абсолютных значениях cosine similarity

## Последствия

- `backend/query/pipeline.py` → функция `_merge()` реализует RRF с параметром `alpha`, читаемым из `Settings.hybrid_alpha` (env `HYBRID_ALPHA=0.7`)
- `hybrid_retriever.py` **не существует** — merge выполняется в `pipeline.py` после `merge_results` ноды
- Оба источника обязательны: если Neo4j возвращает 0 результатов — `graph_map` пуст, RRF корректно работает только на векторных рангах
- `retrieval_score` в ответе API — это RRF-значение, зависит от числа результатов и порядка ранжирования
- При Scale: замена на cross-encoder без изменения интерфейса `_merge()`

## Compliance & Ethics

**Регуляторное соответствие:**
- Merge выполняется локально в Python — данные не покидают периметр
- RBAC фильтрация применяется **до** merge: оба источника (Qdrant и Neo4j) возвращают только документы с `access_level <= user_level`; merge работает исключительно с уже отфильтрованными результатами

**Этические риски и меры снижения:**
- Риск систематического занижения графовых результатов при малом `match_count`: если сущности в запросе не совпадают с онтологией, `graph_signal=0` — граф не вносит вклад. Мера: мониторинг доли graph-only результатов через Langfuse трейсы; расширение онтологии при выявленных пробелах
- Риск «декоративного» графа: если граф всегда проигрывает вектору из-за малого размера. Мера: сравнительный тест `alpha=1.0` vs `alpha=0.7` на golden dataset фиксируется в PoC отчёте
