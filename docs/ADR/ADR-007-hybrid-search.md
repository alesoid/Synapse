# ADR-007: Hybrid Search Merge Formula — 0.7 · vector + 0.3 · graph

**Статус:** Принято  
**Дата:** 11 мая 2026  
**Автор:** Алеся Мороз

---

## Scope

| Этап | Что реализовано | Статус |
|---|---|---|
| **MVP** | Линейная комбинация `0.7 · vector_score + 0.3 · graph_score`, нормализация min-max | ✅ Текущее решение |
| **Scale** | Cross-encoder reranker поверх топ-20 кандидатов; адаптивные веса на основе типа запроса; RRF (Reciprocal Rank Fusion) как альтернатива линейному merge | 🔜 Вне скоупа MVP |

---

## Контекст

Synapse реализует гибридный поиск: векторный (Qdrant, семантическое сходство) и графовый (Neo4j, traversal по связям сущностей). Результаты двух поисков необходимо объединить в единый ранжированный список для передачи в LLM. Ключевые требования:

- Детерминированное слияние результатов (воспроизводимость)
- Возможность настройки весов без изменения архитектуры
- Простота реализации и отладки для MVP
- Оба источника должны влиять на итоговый ранг — граф не должен быть декоративным

---

## Решение

**Взвешенная линейная комбинация** нормализованных скоров:

```python
def merge_results(
    vector_results: list[dict],
    graph_results: list[dict],
    alpha: float = 0.7
) -> list[dict]:
    # Нормализация скоров каждого источника в [0, 1]
    vector_scores = normalize(vector_results)  # min-max
    graph_scores  = normalize(graph_results)

    combined = {}
    for doc_id, score in vector_scores.items():
        combined[doc_id] = alpha * score
    for doc_id, score in graph_scores.items():
        combined[doc_id] = combined.get(doc_id, 0) + (1 - alpha) * score

    return sorted(combined.items(), key=lambda x: x[1], reverse=True)
```

**Коэффициенты:** `alpha=0.7` (вектор), `1-alpha=0.3` (граф).  
Настраиваются через env var `HYBRID_ALPHA=0.7` без изменения кода.

## Альтернативы рассмотрены

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **RRF (Reciprocal Rank Fusion)** | Не требует нормализации скоров, устойчив к выбросам, хорошо работает без тюнинга весов | Менее интуитивен, сложнее объяснить комиссии, нет явного контроля вклада каждого источника | **Отклонён для MVP**, приоритет для Scale |
| **0.5 · vector + 0.5 · graph** | Равный вклад обоих источников, нет предположений о качестве | Граф MVP содержит ~50-100 узлов — его покрытие ниже векторного поиска; равный вес снижает точность | **Отклонён** |
| **Только векторный поиск (alpha=1.0)** | Проще, нет зависимости от качества графа | Теряются связи между документами — ключевое преимущество GraphRAG над обычным RAG | **Отклонён** (противоречит концепции) |
| **Cross-encoder reranker** | Наилучшее качество ранжирования, учитывает запрос при скоринге | Требует отдельной модели, +latency ~2-3 сек, избыточен для MVP | **Отклонён для MVP**, запланирован для Scale |
| **LLM-based reranking** | Высокое качество, гибкость | Двойной вызов LLM — удваивает latency и стоимость инференса | **Отклонён** |

## Trade-offs

**Плюсы взвешенного merge (0.7/0.3):**
- Прозрачность: вклад каждого источника явно задан и легко объяснить
- Настраиваемость: `HYBRID_ALPHA` меняется без перекомпиляции
- Детерминированность: одинаковый запрос всегда даёт одинаковый порядок
- Приоритет вектора (0.7) отражает реальность MVP: граф ещё небольшой (~50-100 узлов), семантический поиск более полный

**Минусы взвешенного merge:**
- Коэффициент 0.7/0.3 выбран эвристически, не на основе offline-оценки на golden dataset
- Линейная комбинация предполагает сопоставимые шкалы скоров — требует нормализации, которая чувствительна к выбросам
- При росте графа (Scale) оптимальный `alpha` может сдвинуться в сторону графа — потребуется повторная калибровка

## Последствия

- `hybrid_retriever.py` реализует merge с параметром `alpha`, читаемым из env
- Оба источника обязательны: если Neo4j возвращает 0 результатов — merge корректно работает только на векторных скорах (граф с нулевым весом)
- Качество merge оценивается на тестовом наборе: сравнение GraphRAG (0.7/0.3) vs чистый векторный поиск (alpha=1.0) — PoC гипотеза
- При Scale: замена на RRF или cross-encoder без изменения интерфейса `hybrid_retriever`

## Compliance & Ethics

**Регуляторное соответствие:**
- Merge выполняется локально в Python — данные не покидают периметр
- RBAC фильтрация применяется **до** merge: оба источника (Qdrant и Neo4j) возвращают только документы с `access_level <= user_level`; merge работает исключительно с уже отфильтрованными результатами

**Этические риски и меры снижения:**
- Риск систематического занижения графовых результатов при коэффициенте 0.3: важные связи между документами могут не попасть в топ. Мера: мониторинг доли graph-only результатов в финальном топ-10 через Langfuse трейсы
- Риск «декоративного» графа: если граф всегда проигрывает вектору из-за малого размера, GraphRAG теряет смысл. Мера: сравнительный тест alpha=1.0 vs alpha=0.7 на golden dataset фиксируется в PoC отчёте — прирост точности обязателен для обоснования решения
